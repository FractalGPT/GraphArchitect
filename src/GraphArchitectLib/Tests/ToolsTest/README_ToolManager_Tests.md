# Тесты для ManagerConverterTools

## Описание

Этот каталог содержит тесты для алгоритма `ManagerConverterTools`, который автоматически строит оптимальные цепочки конвертации данных между форматами.

## Файлы

### 1. `ToolManagerTest.py` - Полный набор тестов с pytest

Комплексный набор тестов, организованный по категориям:

#### Классы тестов:

- **TestGetStrategy** - Тесты основного метода `get_strategy()`
  - Простой прямой путь (A → B)
  - Многошаговый путь (A → B → C)
  - Длинная цепочка (A → B → C → D)
  - Выбор оптимального пути при наличии альтернатив
  - Отсутствие пути между форматами
  - Несуществующие форматы
  - Совпадающие начальный и конечный форматы

- **TestWithAny** - Тесты обработки универсального формата `_Any`
  - Раскрытие `_Any` во все существующие форматы
  - Обработка инструментов без `_Any`
  - Использование `_Any` в реальной стратегии

- **TestCreateAndRun** - Тесты полного пайплайна
  - Создание стратегии и выполнение
  - Обработка отсутствия пути

- **TestEdgeCases** - Граничные случаи
  - Пустой список инструментов
  - Единственный инструмент
  - Несколько инструментов для одной конвертации
  - Циклический граф

- **TestWeightCalculation** - Тесты расчета весов
  - Предпочтение более дешевого пути
  - Учет вероятности успеха

### 2. `ToolManagerDemo.py` - Демонстрационный скрипт

Интерактивная демонстрация работы алгоритма без зависимостей от pytest.

#### Сценарии демонстрации:

1. **Простой путь** - Прямая конвертация PDF → Text
2. **Многошаговый путь** - Конвертация через промежуточные форматы
3. **Оптимальный путь** - Выбор самого дешевого маршрута
4. **Отсутствие пути** - Обработка несвязных форматов
5. **Полный пайплайн** - Создание и выполнение стратегии
6. **Формат _Any** - Раскрытие универсальных инструментов
7. **Сложный граф** - Работа с многочисленными альтернативами

## Структура моковых инструментов

### MockConverterTool

Простая реализация `ConverterTool` для тестирования:

```python
tool = MockConverterTool(
    input_data_format="PDF",      # Входной формат данных
    input_semantic_format="doc",  # Семантический входной формат
    output_data_format="Text",    # Выходной формат данных
    output_semantic_format="doc", # Семантический выходной формат
    tool_name="PDF2Text",         # Название инструмента
    cost_api=5.0,                 # Стоимость API
    prob_true=1.0                 # Вероятность успеха
)
```

### Расчет веса

Вес ребра (инструмента) рассчитывается как:

```
weight = prob_true / (cost_api + 1)
```

Меньший вес означает более предпочтительный путь для алгоритма Дейкстры.

## Как работает алгоритм

1. **Построение графа форматов**
   - Каждый уникальный формат → вершина графа
   - Каждый инструмент-конвертер → ребро графа
   - Несколько инструментов для одной конвертации объединяются

2. **Обработка _Any форматов**
   - Инструменты с входным форматом `_Any` раскрываются
   - Создаются копии для каждого существующего формата

3. **Поиск оптимального пути**
   - Используется алгоритм Дейкстры
   - Находится путь с минимальной суммарной стоимостью

4. **Формирование стратегии**
   - Извлекаются инструменты из найденного пути
   - Возвращается цепочка конвертации

## Пример использования

```python
from graph_architect.ToolRouters.Converters.GraphWithTools.ToolManager import ManagerConverterTools

# Создаем менеджер
manager = ManagerConverterTools(strategy_decoder, runner)

# Определяем инструменты
tools = [
    PDF2TextTool,
    Text2JSONTool,
    JSON2XMLTool,
]

# Получаем оптимальную стратегию
strategy = manager.get_strategy(
    start_format="PDF|doc",
    end_format="JSON|doc",
    tools=tools
)

# Выполняем конвертацию
result = manager.create_and_run(
    input_data="document.pdf",
    start_format="PDF|doc",
    end_format="JSON|doc",
    tools=tools
)
```

## Ожидаемые результаты

### ✓ Успешные сценарии:
- Нахождение прямого пути между форматами
- Построение многошаговой цепочки конвертации
- Выбор оптимального (дешевого) пути при наличии альтернатив
- Корректная обработка универсальных форматов `_Any`

### ✓ Обработка ошибок:
- Возврат `None` при отсутствии требуемых форматов
- Возврат пустого списка при отсутствии пути между форматами
- Корректная работа с циклическими графами
